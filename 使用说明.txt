# SR-Merging: Standard NLP Inference Implementation

## 1. Core Modules

- **`sr_merging/routing.py`**: ERC offline mean compression, SRR online similarity computation, and TCSM Top-K temperature-controlled weighting.
- **`sr_merging/composition.py`**: Keeps all experts resident in memory and combines full LoRA updates using input-specific routing weights.
- **`sr_merging/pipeline.py`**: Classification scoring and text generation in the shared Qwen output space.

## 2. Paper Configuration

- **Backbone model:** Qwen2.5-0.5B-Instruct
- **Embedding encoder:** Potion-base-2M
- **Routing parameters:** K=3, τ=0.8
- **Precision:** FP32
- **Batch size:** 32
- **LoRA configuration:**
  - Rank: r=8
  - Alpha: 32
  - Dropout: 0.1
  - Bias: none
  - Target modules: `gate_proj`, `up_proj`, `down_proj`

The dropout rate of 0.1 is part of the expert configuration and is disabled during inference by `eval()`.

Each expert uses 200 reference samples, following the latest NLP cost configuration. The sampling seed is `42 + expert_index`.

The random sampling procedure is explicitly documented in the README, along with the selected row indices and SHA-256 hashes of the source files.

## 3. Usage

**Installation**

```bash
pip install -e .
```

**Configuration**

Update `configs/paper.json` with the paths to the backbone model, expert adapters, and reference input files.

**Offline reference bank construction**

```bash
python -m sr_merging build-bank --config configs/paper.json
```

**Online classification**

```bash
python -m sr_merging infer --config configs/paper.json --input examples/queries.jsonl --output predictions.jsonl --candidates examples/candidates.json
```

**Online text generation**

```bash
python -m sr_merging infer --config configs/paper.json --input examples/queries.jsonl --output predictions.jsonl --max-new-tokens 64
```

## 4. Key Implementation Details Consistent with the Paper

- **Reference construction:** Each reference embedding is individually normalized before averaging. The resulting mean vector is never renormalized.
- **Online inference:** Only query inputs are encoded during inference. The reference bank is not rebuilt.
- **Input-specific routing:** Experts are selected independently for each input, rather than assigning the entire batch to the same expert subset.
- **LoRA composition:** Full LoRA updates are combined as `sum_i weight_i * scale_i * B_i A_i`. The A and B matrices are never averaged separately.
- **Layer-wise consistency:** All adapted layers share the same input-dependent routing weights.
- **Autoregressive generation:** Routing weights remain fixed throughout generation.
- **Classification consistency:** All inputs share the same candidate label list. Neither candidate selection nor classification-head selection depends on the ground-truth task ID.
- **Label-free routing:** Reference bank construction requires only reference inputs, with expert membership specified in the configuration. Query routing does not require task IDs.

## 5. Required Assets and Limitations

This package does not include pretrained model weights or reference datasets.

The example candidate file contains only four labels and does not represent the complete GLUE evaluation label mapping.

The generation budget of 64 tokens is provided only as a command-line example. The actual generation budget must be explicitly specified.

Adapters trained with incompatible LoRA alpha values or target modules will raise errors. Modifying the JSON configuration cannot make incompatible legacy adapters equivalent to those trained with the paper's configuration.

This version does not include the legacy K=1 or hybrid routing strategies, nor does it report unverified accuracy results from the paper.

## 6. Testing

Run the unit tests using:

```bash
python -m unittest discover -s tests -v
```

The tests use a randomly initialized miniature Qwen model to verify mathematical equivalence and batch-wise routing behavior.

**These tests validate implementation correctness but do not establish downstream task accuracy.**
