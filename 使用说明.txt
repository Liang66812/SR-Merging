SR-Merging NLP 标准推理代码

1. 三个模块位置
   sr_merging/routing.py：ERC 离线均值压缩、SRR 在线相似度、TCSM Top-K 温度权重。
   sr_merging/composition.py：所有专家常驻，按每条输入的权重组合完整 LoRA 更新。
   sr_merging/pipeline.py：共享 Qwen 输出空间下的分类评分和生成。

2. 当前论文参数
   Qwen2.5-0.5B-Instruct；Potion-base-2M；K=3；tau=0.8；FP32；batch=32。
   LoRA r=8，alpha=32，dropout=0.1，bias=none，gate_proj/up_proj/down_proj。
   dropout=0.1 是专家配置；推理时 eval() 会关闭 dropout。
   每专家200条参考沿用最近的NLP成本配置；采样种子42+专家序号。
   随机采样规则在README中明示，并记录选中行号和源文件SHA-256。

3. 使用顺序
   安装：pip install -e .
   配置：修改 configs/paper.json 中模型、专家、参考输入文件路径。
   离线：python -m sr_merging build-bank --config configs/paper.json
   在线分类：python -m sr_merging infer --config configs/paper.json --input examples/queries.jsonl --output predictions.jsonl --candidates examples/candidates.json
   在线生成：python -m sr_merging infer --config configs/paper.json --input examples/queries.jsonl --output predictions.jsonl --max-new-tokens 64

4. 与论文一致的关键点
   参考向量先逐条归一化，再求均值；均值绝不再次归一化。
   推理只编码输入，bank不会重新生成。
   每条输入分别选专家，不把整个batch强制路由到同一组专家。
   组合的是 sum_i weight_i * scale_i * B_i A_i，不分别平均A/B。
   所有层共用同一输入的路由权重；自回归生成期间不改变路由。
   分类候选列表对所有输入完全相同，不按真实任务ID选择候选或分类头。
   参考样本只需输入；构建bank时专家归属来自配置，查询不需要任务ID。

5. 需填写的实际资产
   本包不包含模型权重或参考数据。示例候选只有四个标签，不能作为完整GLUE评估映射。
   生成预算64仅是命令示例，实际预算必须显式指定。
   旧alpha或目标层不一致的adapter会报错；不能通过改JSON把旧权重当作论文训练权重。
   本版本不内置旧K=1/hybrid路由，也不附加未验证的论文准确率。

6. 测试
   python -m unittest discover -s tests -v
   测试使用随机初始化的微型Qwen，核对数学等价性和批量路由，不代表任务准确率。
